Acacia 性能与浏览器排错采集

此包提供测量脚本和现有代码证据。包内没有 Acacia 的真实性能测量结果。脚本语法、统计计算和常见凭证移除已检查；当前执行环境没有可用的 Chromium 可执行文件，浏览器完整运行仍待在你的设备验证。

脚本使用 Acacia 已声明的 Playwright 依赖，浏览器可用电脑上已安装的 Edge 或 Chrome。依赖来源见 https://github.com/TandyBlow/Acacia/blob/0e197bffedf3fcee74a9119d3472d75f7d02bf1d/frontend/package.json 。Playwright 浏览器选项见 https://playwright.dev/docs/browsers#google-chrome--microsoft-edge 。

在 Windows 解压此包，打开 PowerShell，进入解压后的目录。以下命令按之前给出的本地目录 D:\others\Acacia 编写，目录有变化时替换 --project 后的路径。若尚未安装仓库锁定的依赖，先在 frontend 运行 npm ci。

测线上登录页，每种访问方式各记录十遍：

```powershell
node .\acacia-measure.mjs --project D:\others\Acacia\frontend --url https://acacia.tandyblow.top/ --channel msedge --mode load --runs 10 --label production-2026-10-14 --out .\production-load
```

脚本没有读取你现有浏览器的登录信息。没有登录时，取得的结果对应登录页，不能写成编辑器性能。测量登录后的页面时增加 --manual-login，登录在新窗口完成，终端按 Enter 后继续。登录信息在脚本内存中使用，不写入输出文件。

```powershell
node .\acacia-measure.mjs --project D:\others\Acacia\frontend --url https://acacia.tandyblow.top/ --channel msedge --mode load --manual-login --ready-selector ".tiptap[contenteditable]" --runs 10 --label production-editor-2026-10-14 --out .\production-editor-load
```

.tiptap[contenteditable] 是 Tiptap 常用编辑区选择器，运行前确认它匹配当前 Acacia 的实际编辑区。若登录后仍要点击文档才会出现编辑区，自动加载模式会记录超时；这种页面使用下面的手动模式。默认 body 选择器对应页面容器，不代表编辑器可操作。

手动测文档切换、输入、粘贴和保存相关请求，记录操作时的长任务、交互事件、错误信息及 Fetch / XHR 请求时间：

```powershell
node .\acacia-measure.mjs --project D:\others\Acacia\frontend --url https://acacia.tandyblow.top/ --channel msedge --mode manual --label production-editor-2026-10-14 --out .\production-editor-actions
```

在新窗口登录，打开用于测量的文档，然后回到终端按 Enter。输入此次操作的名称，例如 一万字文档切换、公式表格混排粘贴、保存失败后重试。按提示在浏览器操作，等待界面稳定，再回终端按 Enter 保存这一段。下一次输入记录名称时，直接按 Enter 结束。建议使用专门的测试文档，记录它的字符数、公式数、表格大小及操作次数。

本地已运行版本也能测，把 --url 换成实际的本地访问地址。端口以本地启动输出为准，不预设 5173。用于版本对照时，两次使用同样的生产构建方式、浏览器、运行模式、文档、窗口、缓存方式、观察时长和网络条件。开发服务器与服务器上的生产版本不能直接算改善比例。

每次输出目录含 results.json、measurements.csv、browser-records.json、report.md。JSON 保留样本、失败原因、版本标签、环境和时序；CSV 方便汇总；报告计算中位数与这批样本的 p95。采集不保留请求或响应正文、Cookie、请求头、截图和会话存储。常见凭证及 URL 查询参数会从文本中移除，错误文本仍可能包含业务信息，交回材料时保留与测试有关的部分。

首次访问每遍新建浏览器会话。再次访问共用浏览器会话，先预热一遍。脚本没有设置 CPU 或网络降速。ready_selector_ms 含自动化往返时间；LCP 是观察时段截止时的快照；transferSize 可能因跨域权限、缓存或 Service Worker 无法反映全部流量。报告中的 Event Timing 不是正式 INP，快于浏览器阈值的事件可能没有记录。

保存请求耗时与保存完成耗时需要分开：请求时间不含请求发出前的防抖等待，也不自动证明界面已经确认保存。脚本提供请求状态、错误与请求时间；要测从输入到保存成功的完整耗时，可以在临时本地测试分支为输入开始、请求发出、成功确认各加 performance.mark，再用同样的操作对照。已有保存验收测试使用模拟计时器，不能用其运行时长衡量浏览器速度。

浏览器排错记录可以现在复现并补留。用开发者工具的 Network 确认请求状态、顺序和耗时，Performance 记录文档切换或粘贴期间的调用栈与长任务，结合源码定位后重复同一操作验证。Performance 可导出录制，Network 可导出 HAR。用于交付的录制关闭 Screenshots；HAR 选 sanitized 格式，留意正文中是否含测试文档内容。对应官方说明：https://developer.chrome.com/docs/devtools/performance/reference 与 https://developer.chrome.com/docs/devtools/network/reference 。

服务器旧日志需要另行查。仓库中的 deploy/acacia.conf 没有声明站点自己的请求耗时日志格式，实际服务器仍可能继承全局配置；单看该文件无法确定已有日志是否含耗时。取得服务器读权限后，可以查有效配置中的 access_log、log_format、request_time、upstream_response_time，再读取确定的日志路径。若旧日志没有耗时字段，就重新采集，不能从日志时间戳推算已经结束的单个请求时长。

```bash
sudo nginx -T 2>&1 | rg 'access_log|log_format|request_time|upstream_response_time'
```

服务器日志反映它处理请求的情况，浏览器记录反映用户设备上的加载、编辑和网络等待。简历需要按测量对象表述：例如在明确设备与文档规模下测得编辑器操作耗时，或定位了保存响应乱序问题并通过复现验证。改善比例采用相同指标的旧值与新值计算，(旧值 - 新值) / 旧值 × 100%；没有旧版对照时写测量结果，不填改善比例。
